## Who I am

Materials engineer, Linux since I was a kid. The kind of person who
would rather model a failure mode upfront than learn from production
post-mortems. This repo reflects that — a test suite for *dotfiles*, a
`.gitignore` that denies by default with explicit safety locks at the
bottom, and a `CLAUDE.md` that tells coding agents which files they are
not allowed to touch.

If something here looks over-engineered for personal config, that is the
point: I do not keep a separate "home mode".

## What's tracked

The worktree is `$HOME` itself — `~/git/my/dotfiles/` holds the git directory
and, on a fresh box, nothing else. `.gitignore` denies everything by default
and then re-allows an explicit list: a handful of fish configs, the bashrc, the
starship prompt, the `mimeapps.list`, a tiny set of personal scripts under
`.config/my_scripts/`, the shared agent skills under `.agents/skills/`, and the
per-tool agent config for Claude Code, Gemini, Pi and DSH. Anything else
— fish universal variables, history files, caches, session state, credentials —
is ignored by default. The "SAFETY LOCKS" block at the bottom of `.gitignore`
belts the suspenders for the most sensitive paths.

Daily-driver stack: fish, starship, eza, ugrep, fastfetch, kitty,
uv for Python, nvm for Node, and Claude Code for everything else.

## Tests

The repo ships a small fish test suite that pins the behaviors I keep
breaking by accident — alias expansion, the `gen` launcher, completions,
and the `my_scripts/` helpers. Run it with:

```fish
./.config/my_scripts/test_dotfiles.fish
```

It self-isolates via `fish --no-config` so it doesn't pick up whatever is
currently installed under `~/.config/`. Exit code is 0 on success.

## Fresh box

`core.worktree` is local-only config, so a plain clone lands its files in the
wrong place: it checks them out into `~/git/my/dotfiles/` and leaves them there
as a stale second copy, which is what the leftovers in that directory are. Use
`--no-checkout` and repoint the worktree at `$HOME` before the first checkout:

```sh
git clone --no-checkout git@github.com:al4xdev/dotfiles.git ~/git/my/dotfiles
git -C ~/git/my/dotfiles config core.worktree "$HOME"
git -C ~/git/my/dotfiles checkout -f
```

That restores every tracked file in place under `$HOME` and leaves nothing
behind in the clone directory.

## Sync model

There is no automated sync and no separate staging copy: edits happen in place
under `$HOME` and are committed from there.

```sh
git -C ~/git/my/dotfiles status
```

One exception is the DSH plugin wiring. The `alex-*` rows inside
`~/.dsh/profiles/*/cordis.patch.yml` are generated by
`~/git/my/rt/tools/activate.mjs`, which resolves the plugin paths for whatever
machine the repo lands on. After cloning on a new box, re-run it there:

```sh
cd ~/git/my/rt && node tools/activate.mjs --write
```

Until then those rows still point at the previous machine's layout, so the
profiles will show as locally modified — that is the bootstrap catching up, not
a mistake to commit back.
